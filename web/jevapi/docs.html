JevAPI

Should this extracted field be filled automatically, or checked by a person? Free, open source, no sign-up. Try the demo · GitHub

Two ways to use it

Package (runs on your machine, no limits): jevapi for JavaScript and Python. Not on npm/PyPI yet; install from GitHub for now.

Hosted API (this site): three stateless endpoints. Base URL https://jevscope.vercel.app/api/v1.

1. Calibrate on your examples

Send fields you checked by hand. You get back a profile (plain JSON). Keep it and send it with every decide call.

curl -X POST https://jevscope.vercel.app/api/v1/calibrate \
  -H 'Content-Type: application/json' \
  -d '{"examples":[{"field":"total_amount","confidence":0.97,"correct":false}, ...],
       "options":{"costError":20,"fields":{"total_amount":{"costError":100}}},
       "evaluate":true}'

evaluate: true adds a held-out (5-fold) estimate: how much gets auto-filled, how often those fills are wrong, and calibration error before and after.

2. Decide

curl -X POST https://jevscope.vercel.app/api/v1/decide \
  -H 'Content-Type: application/json' \
  -d '{"profile": {...}, "items":[{"field":"invoice_number","value":"INV-2231","confidence":0.99}]}'
{"decisions":[{"field":"invoice_number","action":"fill","confidence":0.97,"lower":0.96,
  "threshold":0.95,"calibrated":true,"source":"field",
  "reason":"Stated 99%; measured on this field's 200 examples, ..."}],"fill":1,"review":0}

No profile? It still works, using the raw confidence, and says so (calibrated: false).

3. Extract with your own AI key (optional)

Send the document's text (read PDFs in your app first) and the fields you want. Put your key in X-Provider-Key. JevAPI asks your provider, then decides each field.

curl -X POST https://jevscope.vercel.app/api/v1/extract \
  -H 'Content-Type: application/json' -H 'X-Provider-Key: YOUR_KEY' \
  -d '{"provider":"openai","model":"YOUR_MODEL_ID","text":"INVOICE INV-2231 ...",
       "fields":[{"name":"invoice_number"},{"name":"total_amount","type":"number"}]}'

Providers: openai, anthropic, gemini. The model id is always yours to choose. JevAPI never pays for AI calls. Your key passes through this server for one request; JevAPI's code never saves or logs it.

4. Check with Jev (your TypeSafe key)

Jev is TypeSafe's decision model. It doesn't write text, it judges. For each field you send a candidate value (from any extractor) or a list of options, and Jev returns the probability that the document really says it. That probability becomes the field's confidence. Put your key in X-Jev-Key. One request per document.

curl -X POST https://jevscope.vercel.app/api/v1/verify \
  -H 'Content-Type: application/json' -H 'X-Jev-Key: YOUR_TYPESAFE_KEY' \
  -d '{"text":"INVOICE INV-2231 ...",
       "fields":[{"name":"invoice_number","value":"INV-2231"},
                 {"name":"currency","options":["INR","USD"]}]}'

No field list? Leave out fields. A resume is read section by section with no AI key (contact details, links, summary, every job, project and degree with its own dates, one field per bullet, every skills line and any other section, wrapped lines joined). It handles the common layouts: dates on the right or on their own line, "Title, Company" or "Company, Title", title and company on separate lines. Jev checks every value, and each question says which job or project it is about (for example "company of job 2, the Associate Software Engineer job"), so Jev can tell two jobs apart. For other text, /verify finds every labelled field in the text ("Invoice No: ...", "Total 48,200") and Jev checks each. On invoices it always asks about the vendor and the currency too, even when they are unlabelled (Jev picks from the letterhead and "payable to" names, and from a currency list). /extract without fields asks your AI for every field it can find. Add "judge":"jev" (plus X-Jev-Key) to an extract call so Jev checks what your AI read. Jev's numbers are raw until you calibrate them on your own labelled documents with /api/v1/calibrate.

Options

OptionDefaultMeaning
costError20One wrong auto-fill costs as much as this many human checks.
costReview1Cost of one human check.
reviewAccuracy1Share of checks that catch the mistake.
maxRisknoneNever auto-fill if the chance of being wrong is above this.
minExamples30Fewer examples than this and a field uses the pooled calibration.
conservativetrueDecide on the 90% lower bound, so a few lucky examples can't unlock auto-fill.

Rule: fill when the lower bound of the measured confidence is at least reviewAccuracy - costReview / costError (and 1 - maxRisk if set). Empty values and missing confidences always go to review.

Limits (free)

calibrate + decide60 requests / minute per IP
extract, verify10 requests / minute per IP
Body1 MB; 5,000 examples; 200 items; 50 fields; 60,000 characters of text

Limits are per server and best effort. The whole service runs on a free hosting plan with monthly caps, so it can pause if it gets very busy. For anything serious, run the package yourself. Errors come back as {"error":{"code","message"}} with a normal HTTP status (400, 405, 413, 429 with Retry-After, 502 for provider errors, 504 for timeouts).

Honest limits

  • A profile only means something for documents like the ones you labelled.
  • The demo's calibration uses synthetic examples.
  • No OCR: scanned images need text first.
