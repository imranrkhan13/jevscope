Fill it, or check it?

Your app pulls fields out of invoices, resumes and forms. JevAPI asks Jev, TypeSafe's decision model, whether the document really says each value. Then it tells you which fields to fill and which ones a person should check, with a reason for each.

How it works

Three steps. One request to Jev per document.

A few lines in your app

Call the free hosted API from any language, or run the open-source package inside your own server.

  • curl, JavaScript and Python examples
  • Recipes for resumes, invoices, receipts, bank statements and forms
  • Your keys, your costs. JevAPI never pays for or marks up model calls
  • Stateless. Nothing you send is kept
Quickstart → 
# Check values against the document
curl -X POST https://jevscope.vercel.app/api/v1/verify \
  -H "X-Jev-Key: $TYPESAFE_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"text": "...",
       "fields": [{"name": "due_date",
                   "value": "12 Sep 2026"}]}'

# Back comes a decision per field
{"field": "due_date",
 "action": "review",
 "confidence": 0.02,
 "reason": "... Below the 95% bar,
            so a person should check it."}

Jev vs Lev

Lev launched on 24 September 2026: an open decision engine, built by Dmitri Sotnikov, that speaks the same API as Jev. Same idea (fast typed yes/no and choice answers with probabilities), different trade-offs. Numbers we did not measure ourselves are marked *.

Jev

Hosted by TypeSafe

Your text goes to TypeSafe's servers. About $0.04 per million input tokens*. Large context: TypeSafe says it can sort thousands of emails in one pass*. One model, no built-in fallback. Nothing to install; you need a TypeSafe key.

Lev

Open, runs locally

One binary on your own machine, works offline, nothing leaves it. Free open weights (laya checkpoints, Apache-2.0). 512-token context on the English model today*. When the fast model is unsure it asks a small local LLM instead: on the author's own adversarial test that lifted correct answers from about 61% to about 92%*.

=

What both share

Neither writes prose; both answer questions you define up front. Independent tests quoted by Lev's author score Jev at 66% on a 150-passage set, tying Claude Haiku 4.5, and find Jev slow to admit "I don't know" (49.7% of the time vs 97-100% for LLMs)*. Treat every confidence as a claim to calibrate, whoever the model is.

Lev's author says it speaks the same wire API as Jev. If so, everything JevAPI does, including extraction-by-verification ("Let Jev find it"), should be able to run on Lev fully offline. We have now tested it ourselves: Lev v0.2.0 answers JevAPI's extraction questions inside our ship job, and the demo shows the head-to-head, same questions to both, on every sample. Our own measured numbers, on real Jev, are public: 10 of 11 field values picked correctly on our small gold set. Sources: Introducing Lev (yogthos.net) · laya weights. * measured or stated by Lev's author or TypeSafe, not by us.
