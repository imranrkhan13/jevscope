# Real evaluation dataset - repos, labels and method

`real.jsonl` is the real counterpart to the simulated `demo.jsonl`. Every
number the Calibration Lab shows for it was measured on real files with real
models. Nothing in it was generated by a simulator.

## The task

Every Python file gets one of seven roles. `real_labels.csv` holds the
measured labels: all 181 Python files in the three held-out repos (requests,
httpx, starlette), each reviewed by hand from its path and contents.

- **entry_point** - where a user or importer arrives: `__init__.py`,
  `__main__.py`, the CLI module, the public `api.py` facade.
- **model** - modules whose primary export is data: data structures, types,
  enums, exceptions, status codes, request/response objects.
- **service** - behaviour: clients, sessions, transports, middleware, routing,
  parsers, encoders.
- **test** - tests and everything that exists to support them, including
  benchmarks and conftest files.
- **config** - packaging, build and settings: `setup.py`, sphinx conf,
  version stamps, configuration objects.
- **utility** - generic helpers not tied to one domain object.
- **legacy** - compatibility shims kept for backwards compatibility.

Judgement calls exist (is `responses.py` a model or a service?) and the CSV is
the answer key that was actually used - disagreement with a choice is a
labelling discussion, not a measurement error.

## How the dataset was built

1. RepoScope's own ingest (`reposcope.ingest.walk`) walked the five training
   repos (flask, jinja, black, pytest, fastapi). Training labels came from the
   documented path rules in `reposcope/calibration/collect_real.py` - cheap on
   purpose. Noise there hurts the models, never the measurement.
2. Two scikit-learn 1.7.2 classifiers were trained on those 320 training
   files only: a multinomial Naive Bayes (`nb`) and a logistic regression
   over TF-IDF (`logreg`). Features: path tokens plus the first ~120 lines.
3. Both models classified all 181 held-out files. Real per-file prediction
   latency is recorded; cost is 0 - both models run locally.
4. The `worth_deep_analysis` noul question: gold is derived from the reviewed
   label by the stated rule `label in {model, service}`; the NB provider's
   noul value is its posterior mass on those two classes.

## What this dataset does not say

- **No API model was queried.** Neither Jev nor any LLM API appears here;
  the providers are the two named scikit-learn models. The Jev-vs-LLM
  comparison needs API access and a larger labelled set.
- **181 files, 3 held-out repos.** Calibration estimates at this size carry
  sampling noise; the report shows intervals.
- **Labels were reviewed by one person**, not by the maintainers of these
  codebases.
- **Thresholds are fitted on this sample** and are optimistic, as the report
  itself states. Hold out a split before shipping one.
